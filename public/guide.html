CaptchaSolve — Complete Guide

Everything you need to set up, run, and integrate your self-hosted CAPTCHA solving service.

01 Quick Start

Get the server running in under 2 minutes. No paid services, no cloud accounts — just Node.js.

1
Make sure Node.js 22+ is installed

The server uses Node's built-in SQLite (v22+). Check your version:

node --version   # must be v22 or higher
2
Open the project folder and install dependencies

Only 3 lightweight packages — no native compilation needed.

cd D:\captcha-solver
npm install
3
Start the server

On first run it prints a demo API key — save it!

node index.js
✅

Server is running. Open these in your browser:

http://localhost:3000 — API docs  ·  http://localhost:3000/worker — Worker Dashboard  ·  http://localhost:3000/admin — Admin Panel

Keep it running in the background

# Install PM2 once
npm install -g pm2

# Start (survives terminal close + auto-restarts on crash)
pm2 start D:\captcha-solver\index.js --name captcha-solver

# Auto-start on Windows reboot
pm2 startup
pm2 save

02 How It Works

The service has three actors: the client (your script), the server (this app), and human workers who solve CAPTCHAs in their browser.

🤖
Client Script
Your Python / Node / PHP automation
REST API
⚡
CaptchaSolve Server
Express + SQLite + Socket.io
WebSocket
👷
Human Worker
Solves in real browser

Client POSTs the CAPTCHA image or reCAPTCHA params to /in.php → gets a task ID back.

Server stores the task in SQLite and instantly pushes it to the next available worker via WebSocket.

Worker sees the challenge in their dashboard, solves it (types text or pastes a token), submits.

Server stores the solution and credits the worker $0.001. Client's balance is debited $0.002.

Client polls GET /res.php?id=TASK_ID every 5 s → receives OK|TOKEN and injects it.

ℹ️

The server is 2captcha-compatible: any library that works with 2captcha.com will work with your server — just change the api_url to http://localhost:3000.

04 Image CAPTCHA

The simplest type. Your script downloads a CAPTCHA image, encodes it as base64, sends it to the API. A worker reads the image and types the answer.

import requests, base64
from captchasolve import CaptchaSolver

solver = CaptchaSolver("YOUR_API_KEY")

# From a file
answer = solver.image("captcha.png")
print(answer)   # "XK92P"

# From a URL
img_bytes = requests.get("https://site.com/captcha.png").content
b64 = base64.b64encode(img_bytes).decode()
answer = solver.image_b64(b64)
const { CaptchaSolver } = require('./captchasolve');
const fs = require('fs');

const solver = new CaptchaSolver('YOUR_API_KEY');
const b64 = fs.readFileSync('captcha.png').toString('base64');
const answer = await solver.image(b64);
console.log(answer);
ℹ️

Send the image as a base64-encoded string in the body parameter. Supports PNG, JPEG, GIF, BMP.

05 reCAPTCHA v2 / v3

reCAPTCHA tokens are cryptographically signed by Google and bound to a specific domain + site key. A worker must open the exact target page and solve the challenge there — a token solved on one domain won't work on another.

How to find the site key

Look in the page's HTML source for:

<!-- Option A: div with data-sitekey -->
<div class="g-recaptcha" data-sitekey="6Le-wvkSAAAAAPBM..."></div>

<!-- Option B: script tag parameter -->
grecaptcha.render({ sitekey: '6Le-wvkSAAAAAPBM...' })

# Or in Python with BeautifulSoup:
soup.find('div', class_='g-recaptcha')['data-sitekey']

Solve and inject the token

import requests
from captchasolve import CaptchaSolver

solver = CaptchaSolver("YOUR_API_KEY")
token  = solver.recaptcha("6Le-wvkSAAAAAPBM...", "https://target.com/login")

# Inject token in the form POST
requests.post("https://target.com/login", data={
    "username":            "my_user",
    "password":            "my_pass",
    "g-recaptcha-response": token,   # ← inject here
})
from selenium import webdriver
from captchasolve import CaptchaSolver

driver = webdriver.Chrome()
driver.get("https://target.com/login")

# Read sitekey from the page
el = driver.find_element("css selector", ".g-recaptcha")
site_key = el.get_attribute("data-sitekey")

# Solve via API
solver = CaptchaSolver("YOUR_API_KEY")
token  = solver.recaptcha(site_key, driver.current_url)

# Inject into page
driver.execute_script(
    f'document.getElementById("g-recaptcha-response").value = "{token}"'
)
driver.find_element("css selector", "button[type=submit]").click()
from playwright.async_api import async_playwright
from captchasolve import CaptchaSolver
import asyncio

async def main():
    async with async_playwright() as p:
        browser = await p.chromium.launch(headless=False)
        page    = await browser.new_page()
        await page.goto("https://target.com/login")

        site_key = await page.get_attribute(".g-recaptcha", "data-sitekey")

        solver = CaptchaSolver("YOUR_API_KEY")
        token  = solver.recaptcha(site_key, page.url)

        # Inject token
        await page.evaluate(
            f'document.getElementById("g-recaptcha-response").value = "{token}"'
        )
        await page.click("button[type=submit]")
        await page.wait_for_navigation()

asyncio.run(main())

06 hCaptcha

Used by Discord, some Cloudflare-protected sites. Same flow as reCAPTCHA — find the site key, solve, inject into the field h-captcha-response.

# Site key is in:  data-sitekey attribute of .h-captcha div
token = solver.hcaptcha("a5f74b19-9e45-40e0-b45d-47ff91b7a6dd", "https://discord.com/register")

requests.post("https://discord.com/register", json={
    "username":           "myuser",
    "h-captcha-response":  token,   # ← key name is different from reCAPTCHA
})

07 🔊 Audio / Voice CAPTCHA

Both 2captcha and this service support audio challenges — they are always solved by human workers, not by AI speech recognition.

⚠️

Common misconception: people assume 2captcha uses AI or speech-to-text for voice CAPTCHAs. It doesn't — real workers listen to the audio and type what they hear. This is more accurate than automated transcription because reCAPTCHA audio is specifically designed to fool STT engines.

How audio CAPTCHA works (step by step)

1
Client requests audio solve

Send the task to the API with method=audio and the audio file URL or base64-encoded MP3/WAV.

2
Worker receives the task

The worker dashboard plays the audio file through their speakers/headphones.

3
Worker types what they hear

reCAPTCHA audio typically says a series of digits, e.g. "3 7 1 9 4". The worker types 37194 and submits.

4
Token returned to client

Same as any other CAPTCHA type — OK|TOKEN from the polling endpoint.

Typical approach with reCAPTCHA (audio path)

# With Selenium: click the audio button, get the audio URL, send to API
from selenium import webdriver

# Switch to reCAPTCHA iframe, click audio button
driver.switch_to.frame("recaptcha iframe")
driver.find_element("id", "recaptcha-audio-button").click()

# Get the audio URL
audio_url = driver.find_element("id", "audio-source").get_attribute("src")

# Submit to API as audio task — worker listens & types answer
# (This is still a plain text-answer task, not a token task)
answer = solver.audio(audio_url)
# → worker hears "3 7 1 9 4" and types "37194"

# Type the answer into the reCAPTCHA audio input box
driver.find_element("id", "audio-response").send_keys(answer)
driver.find_element("id", "recaptcha-verify-button").click()
💡

Audio CAPTCHAs exist because they're required for accessibility (visually impaired users). Ironically that same channel is often easier to solve programmatically — which is why many sites rate-limit or block repeated audio challenge requests.

08 Worker Dashboard

Workers are the humans who solve CAPTCHAs. They register at /worker, log in, and tasks are pushed to them automatically via WebSocket.

Worker workflow

1
Register an account

Go to /worker → click Register → choose a username and password (min 6 chars).

2
Connect and wait

After login, the dashboard connects via WebSocket. The status indicator turns green. Tasks arrive automatically — no need to refresh.

3
Solve each task

For image tasks: see the image, type the text, press Enter or Submit.
For reCAPTCHA / hCaptcha tasks: open the shown URL in a new tab, solve the challenge, run grecaptcha.getResponse() in DevTools console, paste the token back.

4
Earn credits

Each solved task credits $0.001 to the worker's balance. Balance is shown live in the sidebar.

ℹ️

Workers can click "Can't Solve" to skip a task — it returns to the queue for another worker. The client is not charged for failed tasks.

09 How Workers Actually Solve in the Browser

Image CAPTCHA — simple

The dashboard displays the image directly (base64 → <img> tag). Worker reads the distorted text and types it. No special browser setup needed.

reCAPTCHA / hCaptcha — requires the real page

These tokens are domain-locked — Google signs each token with the site key + origin domain. A worker cannot solve a reCAPTCHA "somewhere else" and reuse the token. They must open the actual target page.

🔒

A reCAPTCHA token from login.example.com will be rejected if submitted on shop.example.com — even with the same site key. The domain is part of the cryptographic signature.

The copy-paste method (current system)

The worker dashboard shows the target URL. Worker opens it in a new tab, solves the CAPTCHA, then extracts the token:

// In Chrome DevTools → Console (on the target page after solving):
grecaptcha.getResponse()
// Outputs: "03AGdBq25_XXXXX..."  ← copy this and paste into worker dashboard

// For hCaptcha:
hcaptcha.getResponse()

The extension method (advanced)

Workers install a Chrome extension that automatically captures the token the moment a CAPTCHA is solved on any tab — no copy-paste needed. This is how real 2captcha workers operate. The extension uses content_scripts to hook into the grecaptcha object on every page.

MethodWorker effortWorks onBuild complexity
Copy-paste (current)Medium — open tab, solve, copy tokenAll sitesNone — already works
Chrome extensionLow — just solve, token auto-sentAll sitesHigh — need to build extension
iframe embedLow — solve inlineSites without X-Frame-OptionsMedium

11 Python Client (Easiest Way)

Copy captchasolve.py into your project. No pip install — uses only Python built-ins.

from captchasolve import CaptchaSolver

# Point to your local server
solver = CaptchaSolver("YOUR_API_KEY", api_url="http://localhost:3000")

# ── All available methods ──────────────────────────────────────────
solver.image("path/to/captcha.png")          # → "XK92P"
solver.image_b64("iVBORw0KGgo...")          # → "XK92P"
solver.recaptcha("SITE_KEY", "PAGE_URL")    # → "03AGdBq25..."
solver.recaptcha_v3("SITE_KEY", "PAGE_URL") # → token
solver.hcaptcha("SITE_KEY", "PAGE_URL")    # → token
solver.turnstile("SITE_KEY", "PAGE_URL")   # → token
solver.balance()                             # → 9.984
solver.report_bad("TASK_ID")               # refund bad answer

# Custom timeout (default 120s)
solver = CaptchaSolver("KEY", timeout=180, poll_interval=3)
✅

The Python client is also compatible with the real 2captcha.com — just change api_url="https://2captcha.com". Same code, different server.

12 Real-World Example — Full Login Automation

A complete script that logs into a site with reCAPTCHA using only requests (no browser needed).

import requests
from bs4 import BeautifulSoup
from captchasolve import CaptchaSolver

solver  = CaptchaSolver("YOUR_API_KEY")
session = requests.Session()
session.headers["User-Agent"] = "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"

LOGIN_URL = "https://example.com/login"

# Step 1: Load the login page (grab CSRF token if any)
page = session.get(LOGIN_URL)
soup = BeautifulSoup(page.text, "html.parser")
csrf = soup.find("input", {"name": "_token"})
site_key = soup.find("div", class_="g-recaptcha")["data-sitekey"]

# Step 2: Solve the reCAPTCHA (worker does this)
print("Solving reCAPTCHA...")
token = solver.recaptcha(site_key, LOGIN_URL)
print(f"Got token: {token[:30]}...")

# Step 3: Submit login form with the token
resp = session.post(LOGIN_URL, data={
    "username":             "my_user",
    "password":             "my_password",
    "g-recaptcha-response":  token,
    "_token":               csrf["value"] if csrf else "",
})

if "dashboard" in resp.url or resp.status_code == 200:
    print("✅ Logged in successfully!")
else:
    print(f"❌ Login failed: {resp.status_code}")

14 FAQ

Does 2captcha use AI or always human workers?

Always human workers. 2captcha is a crowdsourcing platform — real people worldwide log in, see CAPTCHAs in their browser, and solve them manually. There is no AI or automated system doing the solving. This is actually the reason services like 2captcha work: Google, hCaptcha, and Cloudflare are specifically trying to block bots and automated solvers, but they can't distinguish a human worker from a real user. The same applies to our system.

Does 2captcha use voice/audio solving?

Yes — and it's still humans. 2captcha workers can solve audio CAPTCHAs by listening to the audio challenge and typing what they hear. There is no automated speech-to-text involved on 2captcha's side. Some third-party tools try to use speech recognition APIs to solve audio CAPTCHAs automatically, but the audio is specifically distorted to defeat those tools — which is why human ears still work better.

What happens if a worker gives a wrong answer?

The client can call GET /res.php?action=reportbad&id=TASK_ID to report a bad answer. The server will refund the client's balance by $0.002. In a production system you'd also want to track worker error rates and penalize/ban workers with too many bad reports. The current system doesn't do this automatically — you'd add that logic in routes/worker.js.

How do I expose this to the internet (not just localhost)?

For production, put nginx in front of the Node.js server:

server {
    listen 443 ssl;
    server_name your-domain.com;
    location / { proxy_pass http://localhost:3000; }
    location /socket.io/ {
        proxy_pass         http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
    }
}

Use Let's Encrypt (free) for SSL. Workers need a stable internet connection to your server to receive tasks via WebSocket.

Can I use this as a drop-in replacement for 2captcha in existing code?

Yes — the API is fully 2captcha-compatible. Any library that supports 2captcha will work. For example, with the official Python 2captcha library:

from twocaptcha import TwoCaptcha
solver = TwoCaptcha('YOUR_KEY', defaultTimeout=120,
                    server='http://localhost:3000')
result = solver.recaptcha(sitekey='...', url='...')
What's the database file and can I reset it?

The database is D:\captcha-solver\captcha.db — a single SQLite file. To reset everything (clear all tasks, workers, API keys), simply delete captcha.db and restart the server. It will recreate the schema and generate a new demo API key on startup.

How do I change how much workers earn per solve?

Open D:\captcha-solver\index.js and find these two lines:

// Credit worker $0.001 per solve
'UPDATE workers SET balance = balance + 0.001 ...'
// Charge client $0.002 per solve
'UPDATE api_keys SET balance = balance - 0.002 ...'

Change the values to whatever you want. Restart the server for changes to take effect.
